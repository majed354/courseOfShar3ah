# تجربة معادلة مقررات القرآن وعلومه

نسخة محلية تعمل فعلًا، مخصصة لبكالوريوس القرآن وعلومه في خطتي 39 و47.
تقبل توصيف PDF واحدًا أو مفردات مدخلة يدويًا، وتتيح التجربة بمقرر من الفهرس.
الخدمة ليست مضافة إلى موقع الإنتاج بعد؛ مجلدها والمحرك والمخرجات خارج قائمة
النشر في `scripts/build-site.mjs`. لا تغير المعادلات المعتمدة أو نواتج المقررات.

## السياسة التي اعتمدها المستخدم

- مقام التغطية هو **عدد مفردات المقرر الهدف**، وليس ساعاتها أو كلماتها.
- المفردة تُحتسب في الحساب الدقيق عند توافق ≥80%، وفي المتسامح عند ≥60%.
- حد تغطية المقرر هو ≥80% في الحسابين. القبول الدقيق أولًا، ثم القبول بالتسامح،
  ثم عدم القبول. نقص المصدر/المقارنة حالة «المعلومات لا تكفي».
- المقارنة اتجاهية من المقرر المرفوع إلى مقرر البرنامج والخطة المحددين.
- كل صف موضوعي مطبوع وحدة أولية؛ تدمج تتمته عبر الصفحات، وتستبعد المراجعة
  والاختبارات. يُراجع تقسيم الوحدات في الواجهة قبل الحساب، خصوصًا إذا جمع صف
  واحد عدة موضوعات. لا يعيد المحرك احتساب صف المصدر نفسه لتغطية صفوف متعددة؛
  يحتاج اختلاف التجميع إلى تفصيل موضوعي ظاهر في شاشة المراجعة.
- درجة توافق المفردة تقدير دلالي للمحتوى الفعلي ونطاقه، وليست cosine ولا احتمالًا
  إحصائيًا معايرًا. لا تكفي صلة الموضوع بالتخصص أو تشابه مهارة الحفظ/التفسير.
- الساعات المعتمدة ظاهرة في التقرير، لكنها لا تغير حكم المفردات؛ اللوائح
  والشروط الأكاديمية الإضافية ليست منفذة في هذه التجربة.

## التشغيل

من جذر المستودع الوحيد:

```bash
/Users/majd/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 -m venv --system-site-packages .venv-equivalency
.venv-equivalency/bin/python -m pip install -r equivalency-pilot/requirements.txt
.venv-equivalency/bin/python -m scripts.equivalency build
.venv-equivalency/bin/python -m scripts.equivalency serve --port 8798
```

افتح `http://127.0.0.1:8798`، أو شغّل `start.command` بعد تجهيز البيئة.
يتطلب البحث الدلالي `qwen3-embedding:0.6b` المثبت في Ollama، والتدقيق
`qwen3.8:27b-q8_0`. يمكن تغيير نموذج التدقيق بـ`--model` إلى نموذج محلي مثبت.
تعذر التضمين يظهر تنبيهًا ويعيد البحث النصي؛ تعذر التدقيق يمنع الحكم بدل اختلاقه.
لا ينزل المحرك نموذجًا تلقائيًا ولا يستعمل نموذجًا سحابيًا أو مفتاح API.

الخادم يستمع على loopback فقط، ويتحقق من Host ورمز الطلبات والمصدر، ولا يسمح
بطلبات تغيير من مواقع أخرى. يفرض حد 12 ميغابايت و40 صفحة للتوصيف. ملفات المستخدم
والتقارير وذاكرة النماذج في `runtime/equivalency/` المستبعد من Git والنشر.
لا تكفي هذه النسخة لفتح الخدمة للعامة؛ يلزم قبل ذلك عزل جلسات المستخدمين
وتوثيق الدخول وحدود المهام والحذف، واختبار تشغيل المحرك الدائم.

## مسار المصدر والتصحيح

1. يعاد استعمال `assets/js/site-edits.js` نفسه لتطبيق تعديلات الواجهة قبل
   اختيار توصيف الرمز والاسم والبرنامج والخطة. لا يُستبدل بتوصيف برنامج آخر.
2. يستخرج جدول الموضوعات هندسيًا مع الصفحة وbbox وبصمة PDF، وتوصل الخلية
   الممتدة عبر الصفحات مع حفظ جميع أجزاء موضعها.
3. يحفظ `text` المستخرج الأصلي، وتوضع القراءة المستكملة في `corrected_text`
   مع طريقة التصحيح وسببه. أذن المستخدم بالاستدلال السياقي؛ لا تُضاف مفردات
   جديدة إلى المصدر ولا يتغير PDF. لا يثبت التصحيح أنه اعتماد أكاديمي.
4. القراءات البصرية الخاصة في `topic-readings.json` مقيدة ببصمة PDF وبصمة
   النص الخام معًا؛ لا تنتقل إلى ملف متغير. تصحيحات المستخدم في الواجهة
   محفوظة داخل تقريره، ولا تعدل الفهرس العام.
5. يمنع تأكيد المقارنة حتى مراجعة نصوص المقررين. تظل جميع سجلات الفهرس
   `reviewed: false`؛ استخراج النص ليس شهادة مراجعة بشرية لكل مقرر.
6. تقارن المفردات كاملة في النموذج المحلي وفق JSON Schema. يتحقق الكود من
   المعرفات والدرجات واكتمال تغطية الهدف وورود الاقتباسات في نصوصها. المقارنة
   المبتورة أو غير الصالحة تمنع الحكم. التطابق النصي الكامل لا يحتاج نموذجًا.
7. يحسب الكود مقابلات أقصى عدد دون تكرار لكل عتبة، ويحسم بالعدد الصحيح قبل
   تقريب النسبة للعرض. يضم التقرير النصين والأسباب والاستكمالات وبصمات المصدر
   والنموذج والفهرس، مع الطباعة وتنزيل HTML وJSON.

الفهرس مربوط ببصمات `data.json` و`site-edits.json` والقراءات. يتحقق الخادم أيضًا
من PDF الهدف ومصدر الفهرس المستخدم قبل المقارنة وبعدها. أعد البناء بعد تغيرها.

## التحقق وحدود القبول

```bash
.venv-equivalency/bin/python -m unittest tests.test_course_equivalency -v
.venv-equivalency/bin/python scripts/verify_course_outcomes.py
.venv-equivalency/bin/python -m unittest discover -s tests
npm test
npm run build
```

الاختبارات تغطي 80/80/60، وعدم تقريب حد القبول، ومنع التكرار، والاقتباس المختلق،
ونقص المقارنة، واتجاه المقام، واختيار النسخة بعد تعديلات الموقع، ووصل الخلايا
والقالب القديم واستعادة الرموز التالفة. سجل الدفعة ونتائج أمثلة المقارنة في
`review-batches/equivalency-quran-20261102.json`.

التجربة الفنية لا تثبت دقة النموذج على جميع الحالات. يلزم بنك مستقل يحكم عليه
مختصون، خصوصًا الحالات الحدّية واختلاف تجميع الموضوعات، قبل اعتماد أحكام عامة
أو ضبط نموذج. مخرجات المقارنة الحالية تجريبية ومفسرة، وليست قرارات لجنة معادلات.
